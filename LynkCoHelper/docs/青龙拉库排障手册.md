# 青龙面板「拉取失败」排障手册

适用于：`ql repo` / 订阅拉库 / `ql raw` 单文件拉取失败。
配套文档：`青龙面板部署指南.md`。

---

## 零、先给结论：本项目最常见的两个坑

1. **拉错仓库**：青龙版改造只存在于 `zhaosongbing/LynkCoHelper-QingLong`。
   原仓库 `zhaosongbing/LynkCoHelper` 里**没有** `lynkco_qinglong.py`，拉它必然是「拉到旧文件」或「任务找不到入口」。
2. **路径是两层**：拉库后目录名 = 仓库名，仓库里又有 `LynkCoHelper/` 子目录，所以正确路径是
   `/ql/scripts/LynkCoHelper-QingLong/LynkCoHelper/lynkco_qinglong.py`，
   任务命令必须写成 `task LynkCoHelper-QingLong/LynkCoHelper/lynkco_qinglong.py`。

## 二、日志在哪里看

| 入口 | 路径 |
| --- | --- |
| 面板 UI（首选） | **定时任务** → 找到拉库任务 → 点「日志」按钮 |
| 订阅拉库 | **订阅管理** → 对应订阅 → 点「日志 / 运行记录」 |
| 容器内日志文件 | `/ql/data/log/<任务ID 或订阅ID>/<时间戳>.log` |
| 实时跟踪 | `docker exec -it ql bash -c "ls -lt /ql/data/log \| head -20"` |

看日志时的要点：

- 拉库日志通常**先打印 git clone 的输出，再打印复制了哪些文件**。
  如果前半段就报错 → 网络/鉴权/地址问题；如果前半段成功、后半段「复制 0 个文件」→ 白黑名单问题。
- 日志里会回显青龙实际拼出来的命令和参数，用它来核对参数有没有被填错位置。

## 三、典型报错 → 原因 → 处理

### 网络类

| 报错 | 含义 | 处理 |
| --- | --- | --- |
| `Could not resolve host: github.com` | DNS 解析失败 | 容器内换 DNS：`Docker run` 加 `--dns 8.8.8.8`，或改 `/etc/resolv.conf`；裸机改 `/etc/resolv.conf` |
| `Failed to connect to github.com port 443: Connection timed out` | 出口被墙/无外网 | 配代理或用镜像域名（见第四节） |
| `CONNECT tunnel failed, response 502` | 代理本身不通或不允许该域名 | 换代理地址/端口；确认代理支持 CONNECT 到 github.com:443 |
| `gnutls_handshake() failed` / `TLS connect error` | 容器 CA 证书过旧 | `docker exec ql apk update && apk add --no-cache ca-certificates`（alpine）或 `apt-get install --reinstall ca-certificates` |
| `early EOF` / `index-pack failed` | 克隆中途断流 | 重试；或改用镜像/代理，避免大仓库浅克隆超时 |
| curl 返回 `000` | 完全不通 | 同「Connection timed out」 |

### 地址 / 分支类

| 报错 | 含义 | 处理 |
| --- | --- | --- |
| `repository 'https://github.com/xxx/yyy.git/' not found` | 仓库名拼错、仓库已删、或仍是私有却当公开拉 | 核对用户名/仓库名大小写；确认仓库真的已 `PUBLIC` |
| `Remote branch main not found` / `pathspec 'main' did not match` | 默认分支不是 main（可能是 master） | 分支字段改 `master`，或去仓库页看实际默认分支 |
| `error: pathspec ... did not match any file(s) known to git` | 分支字段填错，被当成路径了 | 参数顺序错位，见第四节「参数顺序」 |
| raw 拉取 `404: Not Found` | 用了 `github.com/.../blob/...` 当 raw 链接，或分支/文件名错 | 改成 `raw.githubusercontent.com/<user>/<repo>/<branch>/<path>` |

### 过滤类（拉成功但没有文件）

| 现象 | 含义 | 处理 |
| --- | --- | --- |
| 日志显示 clone 成功，但「复制 0 个文件」 | 白名单把所有文件都过滤掉了 | 白名单填**路径子串**，本项目填 `LynkCoHelper`；先留空白名单测试一次 |
| 拉到了，但缺 `lynkco_qinglong.py` | 拉错仓库 / 该分支没有此文件 | 核对仓库与分支 |
| 拉到了，但定时任务没自动创建 | 「自动添加任务」关闭，或文件后缀不在 extensions 里 | 打开开关；或手动新建任务 |
| 任务报错「文件不存在」 | 路径少写一层仓库名 | 用 `task LynkCoHelper-QingLong/LynkCoHelper/lynkco_qinglong.py` |

### 鉴权 / 限流类

| 报错 | 含义 | 处理 |
| --- | --- | --- |
| `Permission denied (publickey)` | SSH 拉私有仓库没配私钥 | 订阅类型选私有仓库并填私钥，或改用 https + token |
| `Support for password authentication was removed` | GitHub 已禁用密码认证 | 必须用 PAT；链接写成 `https://<user>:<PAT>@github.com/...` |
| `Authentication failed` | token 失效/权限不足 | 重新生成 PAT，勾 `repo`（私有库必需） |
| `429` / `rate limit exceeded` / `secondary rate limit` | API 限流 | 匿名 API 限 60 次/小时；改用 git clone / raw 方式，或配 token 提高额度 |
| Gitee：`请输入用户名密码` | 私有 Gitee 仓库 | 同样用 token 或改公开 |

### 青龙环境类

| 报错 | 含义 | 处理 |
| --- | --- | --- |
| `ql: command not found` | PATH 未加载（常见于 cron 或裸机） | 用绝对路径 `/usr/local/bin/ql`；或在任务里先 `source /root/.bashrc` |
| `node: not found` / `python3: not found` | 容器依赖缺失或镜像被精简 | 重装/换官方镜像；`docker exec ql apk add nodejs python3` |
| `git: not found` | 容器没装 git | `docker exec ql apk add git`（alpine）/ `apt-get install -y git` |
| 老版本青龙不支持订阅功能 | 版本过旧 | 升级到 v2.11+（`ql update` 或重拉镜像） |

## 四、修复方案

### 1. 地址填写规范

| 场景 | 正确写法 |
| --- | --- |
| 整库（推荐） | `https://github.com/zhaosongbing/LynkCoHelper-QingLong.git`（带不带 `.git` 均可） |
| 单文件 raw | `https://raw.githubusercontent.com/zhaosongbing/LynkCoHelper-QingLong/main/qinglong/lynkco_qinglong_single.py` |
| 私有库 https | `https://<用户名>:<PAT>@github.com/zhaosongbing/LynkCoHelper-QingLong.git` |
| 私有库 ssh | `git@github.com:zhaosongbing/LynkCoHelper-QingLong.git` + 青龙填私钥 |

❌ 错误写法：`https://github.com/zhaosongbing/LynkCoHelper-QingLong/blob/main/qinglong/xxx.py`（这是网页地址，不是可拉取地址）。

### 2. 参数顺序（最容易踩）

青龙 v2.11+ 的顺序是：

```
ql repo <仓库地址> <白名单> <黑名单> <依赖文件> <分支> <文件后缀>
```

本项目实测可用的完整命令：

```bash
ql repo https://github.com/zhaosongbing/LynkCoHelper-QingLong.git "LynkCoHelper" "docs|previews|tools" "requirements.txt" "main"
```

若你的青龙版本更老（参数是 `<地址> <分支> <白名单> <黑名单>`），命令会变成「分支被当白名单」，表现为拉不到文件。
**规避办法：直接用面板「订阅管理 → 新建订阅」的图形表单**，每个字段有明确标签，不会填错位置。

### 3. 代理 / 镜像加速

青龙里配代理的位置（任选其一）：

- **订阅表单里直接有「代理」输入框**，填 `http://<host>:<port>`；
- 容器级：`docker run -e http_proxy=... -e https_proxy=...`，或进容器在 `/ql/config/config.sh` 里 `export http_proxy=...`；
- 拉库命令临时走代理：`http_proxy=http://x:y https_proxy=http://x:y ql repo ...`

镜像加速域名（把 github.com 前缀拼到镜像后）：

```
https://ghproxy.com/https://github.com/zhaosongbing/LynkCoHelper-QingLong.git
https://gh-proxy.com/https://github.com/zhaosongbing/LynkCoHelper-QingLong.git
https://gitclone.com/github.com/zhaosongbing/LynkCoHelper-QingLong.git
```

raw 单文件加速（jsDelivr，国内通常可用）：

```
https://cdn.jsdelivr.net/gh/zhaosongbing/LynkCoHelper-QingLong@main/qinglong/lynkco_qinglong_single.py
```

> 镜像站随时可能失效，且第三方镜像有读取你公开仓库的隐私风险；能用代理就优先用代理。
> `hub.fastgit.org`、`raw.fastgit.org` 已停止服务，不要再用了。

### 4. 无法自动拉取时的替代做法（兜底，一定能成）

按优先级：

1. **容器内直接下载**
   ```bash
   docker exec -it ql bash -c "mkdir -p /ql/scripts/LynkCoHelper && \
     curl -fsSL -o /ql/scripts/LynkCoHelper/lynkco_qinglong_single.py \
     https://cdn.jsdelivr.net/gh/zhaosongbing/LynkCoHelper-QingLong@main/qinglong/lynkco_qinglong_single.py"
   ```
2. **宿主机下载后拷进去**
   ```bash
   curl -fsSL -o ./lynkco_qinglong_single.py https://cdn.jsdelivr.net/gh/zhaosongbing/LynkCoHelper-QingLong@main/qinglong/lynkco_qinglong_single.py
   docker cp ./lynkco_qinglong_single.py ql:/ql/scripts/lynkco_qinglong_single.py
   ```
3. **面板手动粘贴**：脚本管理 → 新建脚本 → 把单文件内容粘进去（单文件版约 2300 行，纯标准库 + requests）。
4. **离线 zip**：在能上网的机器 `git clone` 后打包，用面板「脚本管理 → 上传」或 `docker cp` 放进 `/ql/scripts/`。

用以上任意方式放好文件后，新建定时任务 `task lynkco_qinglong_single.py`，定时规则 `8 8 * * *`。

## 五、一键自检脚本（在青龙容器里跑）

把下面整段粘到「定时任务 → 新建任务 → 命令」里手动运行一次，或 `docker exec -it ql bash` 后执行：

```bash
echo "===== 1. 基础环境 ====="
ql -v 2>&1 | head -2; git --version; node -v 2>&1; python3 -V 2>&1

echo "===== 2. DNS ====="
getent hosts github.com || echo "DNS 解析失败"

echo "===== 3. 连通性（code 000 = 完全不通）====="
curl -sS -m 10 -o /dev/null -w "github.com        : %{http_code}\n" https://github.com
curl -sS -m 10 -o /dev/null -w "codeload(git)     : %{http_code}\n" https://codeload.github.com
curl -sS -m 10 -o /dev/null -w "raw.githubusercontent: %{http_code}\n" https://raw.githubusercontent.com
curl -sS -m 10 -o /dev/null -w "jsDelivr          : %{http_code}\n" https://cdn.jsdelivr.net

echo "===== 4. 代理环境变量 ====="
env | grep -i proxy || echo "未设置代理"

echo "===== 5. 真实克隆测试 ====="
rm -rf /tmp/qltest
if timeout 90 git clone --depth 1 https://github.com/zhaosongbing/LynkCoHelper-QingLong.git /tmp/qltest; then
  echo "克隆成功，入口文件："; ls -l /tmp/qltest/LynkCoHelper/lynkco_qinglong.py
else
  echo "克隆失败 —— 网络/地址/鉴权三选一，看上面的输出定位"
fi

echo "===== 6. scripts 目录现状 ====="
ls /ql/scripts 2>/dev/null | head -20
```

判读：

- 第 3 步全 `000` 或超时 → 网络问题，走「代理 / 镜像」或用第四节兜底方案。
- 第 3 步通但第 5 步失败 → 地址/分支/鉴权问题。
- 第 5 步成功 → 网络和地址都没问题，问题在青龙的参数填写（白黑名单/分支位置）或任务路径，回到第三节「过滤类」。
