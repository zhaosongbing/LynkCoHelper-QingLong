# 青龙面板（Qinglong Panel）部署指南

把 LynkCoHelper 从「本地脚本 / GitHub Actions」改造为「青龙定时任务」。改造保持原有业务逻辑零改动，只是在外面加了一层青龙适配：入口脚本、依赖自检、环境变量、多账号、双通道通知、退出码。

---

## 一、改造内容一览

| 文件 | 类型 | 说明 |
| --- | --- | --- |
| `LynkCoHelper/lynkco_qinglong.py` | 新增 | **青龙入口**。拉库方式下的定时任务直接指向它 |
| `LynkCoHelper/qinglong_notify.py` | 新增 | 青龙自带通知渠道适配（sendNotify.py / notify.js） |
| `LynkCoHelper/tools/build_qinglong_single.py` | 新增 | 打包器：把多模块合并为单文件版脚本 |
| `qinglong/lynkco_qinglong_single.py` | 新增（生成物） | 单文件版，供「新建脚本粘贴」或 `ql raw` 使用 |
| `LynkCoHelper/lynkco_common.py` | 改动 | `env.json` 路径可配置，青龙下默认落 `/ql/data/lynkco_env.json`；新增 `LYNKCO_DISABLE_ENV_WRITE` |
| `LynkCoHelper/lynkco_login.py` | 改动 | 新增 `LYNKCO_SKIP_TOKEN_CACHE`（多账号防串号） |

针对青龙环境做的 6 项适配：

1. **路径自包含**：入口脚本把自身目录插入 `sys.path`，无论青龙用 `task xxx.py`、`python3 /ql/scripts/...` 还是面板按钮启动，都能 import 同目录的 `lynkco_*.py`。
2. **依赖自检**：`requests` 缺失时自动 `pip install`（优先清华镜像，可用 `LYNKCO_PIP_MIRROR` 改），不会因依赖没装直接崩。
3. **配置自愈**：`env.json` 默认落到 `/ql/data/lynkco_env.json`，不会被 `ql repo` 拉库覆盖；可用 `LYNKCO_ENV_FILE` 自定义。
4. **多账号**：`LYNKCO_REFRESH_TOKEN` / `LYNKCO_DEVICE_ID` / `LYNKCO_TOKEN` 支持换行或 `&` 分隔，逐个执行后汇总；多账号自动关闭 env.json 缓存与回写，防止串号。
5. **双通道通知**：Bark（项目自带）+ 青龙面板通知渠道，可同时启用。
6. **明确退出码**：全部账号成功 `exit 0`，任一失败 `exit 1`，青龙据此标记任务状态并按「任务失败时推送」告警。

## 二、部署方式 A：拉库（推荐，便于后续升级）

### 1. 拉库命令

青龙 → 定时任务 / 订阅管理，执行：

> ⚠️ **注意仓库别拉错**：青龙版改造只存在于 **`LynkCoHelper-QingLong`** 仓库，
> 原仓库 `zhaosongbing/LynkCoHelper` 里没有 `lynkco_qinglong.py`，拉它一定跑不起来。

```bash
ql repo https://github.com/zhaosongbing/LynkCoHelper-QingLong.git "LynkCoHelper" "docs|previews|tools|tests" "requirements.txt" "main"
```

参数依次为 `仓库地址` `白名单` `黑名单` `依赖文件` `分支`：

| 参数 | 值 | 作用 |
| --- | --- | --- |
| 白名单 | `LynkCoHelper` | 只拉 `LynkCoHelper/` 目录（含全部 `lynkco_*.py`、`qinglong_tasks.json`） |
| 黑名单 | `docs\|previews\|tools\|tests` | 排除文档、预览图、AppSecret 提取工具与单元测试（青龙上用不到） |
| 依赖文件 | `requirements.txt` | 拉库后自动 `pip install requests` |
| 分支 | `main` | 默认分支 |

> 也可以在「订阅管理 → 新建订阅」里图形化填写同样的内容，效果一致。

### 1.1 私有仓库怎么拉

> 仓库当前已设为公开。若你改成私有，或 fork 后设为私有，则需要下面的认证方式。

私有仓库无法匿名 clone，先配置认证，二选一：

- **SSH**：公钥加到 GitHub 账号，青龙订阅类型选「私有仓库」，填入 SSH 私钥，链接用
  `git@github.com:zhaosongbing/LynkCoHelper-QingLong.git`
- **Token**：生成一个 PAT（勾选 repo 只读即可），链接写成
  `https://<用户名>:<TOKEN>@github.com/zhaosongbing/LynkCoHelper-QingLong.git`

> 单文件版不建议走私有仓库的 `ql raw`：raw.githubusercontent.com 对私有仓库需要带
> Authorization 头，面板一般不支持。私有场景直接用上面的拉库方式更省事。

### 2. 拉库后的目录与任务命令

```
/ql/scripts/LynkCoHelper-QingLong/LynkCoHelper/
├── lynkco_qinglong.py     ← 青龙入口
├── lynkco_ql_tasks.py     ← 任务自动注册（见 §2.1）
├── qinglong_tasks.json    ← 任务清单（见 §2.1）
├── lynkco_common.py  lynkco_login.py  lynkco_sign.py
├── lynkco_share.py   lynkco_notify.py lynkco_daily_tasks.py
├── qinglong_notify.py
└── requirements.txt
```

> 目录第一层是**仓库名** `LynkCoHelper-QingLong`，第二层才是仓库内的 `LynkCoHelper/` 包目录，
> 任务命令两层都要写，少写一层会报「文件不存在」。

新建定时任务：

- **名称**：领克每日任务
- **命令/脚本**：`task LynkCoHelper-QingLong/LynkCoHelper/lynkco_qinglong.py`
- **定时规则**：`8 8 * * *`（每天 08:08，青龙 cron 为 `分 时 日 月 周`，也支持首位加秒）

> 若订阅开了「自动添加任务」，青龙会给每个 `lynkco_*.py` 都建一个任务。请**只保留 `lynkco_qinglong.py` 这一个**，其余删除或禁用——`lynkco_login.py` 需要交互式输入滑块结果，`lynkco_sign.py` / `lynkco_share.py` 单独跑属于重复执行。

### 2.1 让青龙在拉库时自动把任务建好

手工建任务可以省掉：仓库自带 `qinglong_tasks.json` 清单 + `lynkco_ql_tasks.py` 注册器，
拉库后跑一次 `sync` 就会按清单**幂等**地把任务建进面板（重复拉库不会建重，青龙自己建的
任务也会按 command 认出来并校正规则）。

在订阅表单的「执行后」填：

```bash
task LynkCoHelper-QingLong/LynkCoHelper/lynkco_ql_tasks.py sync
```

需要青龙 OpenAPI 凭据（环境变量 `QL_TOKEN`，或 `QL_CLIENT_ID` + `QL_CLIENT_SECRET`，
应用需勾选 `crons` 权限）。字段说明、幂等/去重/清理规则、排障见
[`青龙自动创建定时任务.md`](青龙自动创建定时任务.md)；白名单记得包含
`lynkco_ql_tasks.py` 与 `qinglong_tasks.json`，否则「执行后」命令找不到脚本。

## 三、部署方式 B：单文件（不方便拉库时）

适合只想用面板「脚本管理 → 新建脚本」粘贴，或用 `ql raw` 拉单个文件的场景。

- 直接用仓库里的生成物：`qinglong/lynkco_qinglong_single.py`
- 或自己重新生成（改动源码后建议重新生成）：

```bash
python3 LynkCoHelper/tools/build_qinglong_single.py
# 产物：qinglong/lynkco_qinglong_single.py（约 2300 行，纯标准库打包，无外部依赖）
```

用 `ql raw` 添加（仅公开仓库可用，私有仓库请走上面的拉库方式）：

```bash
ql raw https://raw.githubusercontent.com/zhaosongbing/LynkCoHelper-QingLong/main/qinglong/lynkco_qinglong_single.py
```

> 注意 raw 链接是 `raw.githubusercontent.com`，**不是**浏览器里的 `github.com/.../blob/...`，
> 否则一定 404。国内访问 raw 域名常不通，可换 jsDelivr：
> `https://cdn.jsdelivr.net/gh/zhaosongbing/LynkCoHelper-QingLong@main/qinglong/lynkco_qinglong_single.py`

任务命令：`task lynkco_qinglong_single.py`

> 单文件版用 `ast` 剔除跨模块 import，再把自身注册为各子模块名，因此 `import lynkco_common` 与 `lynkco_common.NATIVE_APP_KEY` 这类引用在合并后依然成立，功能与多模块版完全一致。

## 四、环境变量配置（青龙 → 环境变量）

> ⚠️ **所有变量的「自动拆分」请关闭**。多账号由脚本自己按换行 / `&` 解析，开启自动拆分反而会让青龙把值切成多条记录。

### 必需

| 变量 | 说明 |
| --- | --- |
| `LYNKCO_APP_SECRETS` | 签名密钥集合，**必须是单行 JSON**，5 个字段缺一不可：<br>`{"nativeAppKey":"","nativeAppSecret":"","nativeAppCode":"","loginAppCode":"","glDevId":""}`<br>获取方式见 `docs/AppSecret_逆向分析记录.md` |
| `LYNKCO_REFRESH_TOKEN` | refreshToken（约 30 天有效），**推荐方式**，可自动续期 |
| `LYNKCO_DEVICE_ID` | 与 refreshToken 配套的设备 id（必须同一次抓包） |

不愿合并成一个 JSON 时，也可用 5 个独立变量代替 `LYNKCO_APP_SECRETS`：
`LYNKCO_NATIVE_APP_KEY`、`LYNKCO_NATIVE_APP_SECRET`、`LYNKCO_NATIVE_APP_CODE`、`LYNKCO_LOGIN_APP_CODE`、`LYNKCO_NATIVE_GL_DEV_ID`（优先级：独立变量 > `LYNKCO_APP_SECRETS` > `env.json`）。

### 备选

| 变量 | 说明 |
| --- | --- |
| `LYNKCO_TOKEN` | 静态 token（约 30 分钟有效）。仅在 refreshToken 不可用时的兜底，需要频繁手动更新 |

### 可选

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `LYNKCO_BARK_KEY` | 空 | Bark 推送 Key，不配则跳过 Bark |
| `LYNKCO_BARK_ICON` | 空 | Bark 推送图标 URL |
| `LYNKCO_QL_NOTIFY` | `1` | 是否走青龙面板自带通知渠道，`0` 关闭 |
| `LYNKCO_DO_SHARE` | `1` | 是否执行分享任务，`0` 只签到 |
| `LYNKCO_ENERGY_DELAY` | `5` | 签到/分享后查询积分前的等待秒数 |
| `LYNKCO_TIMEOUT` | `30` | 单次请求超时秒数 |
| `LYNKCO_ENV_FILE` | `/ql/data/lynkco_env.json` | env.json 存放路径 |
| `LYNKCO_PIP_MIRROR` | 清华源 | 自动安装 requests 用的 pip 镜像 |
| `LYNKCO_SKIP_TOKEN_CACHE` | 自动 | `1` 跳过 env.json 缓存 token（多账号自动开启） |
| `LYNKCO_DISABLE_ENV_WRITE` | 自动 | `1` 禁止回写 env.json（多账号自动开启） |
| `TZ` | 容器默认 | 建议 `Asia/Shanghai`，否则日志时间与定时任务时间会差 8 小时 |

### 多账号写法

```
LYNKCO_REFRESH_TOKEN = bearerAAAA...&bearerBBBB...
LYNKCO_DEVICE_ID     = device111&device222
```

或用换行分隔（青龙环境变量的值支持多行）。两个变量按序号一一对应；数量不足时 `LYNKCO_DEVICE_ID` 复用第一个值。

## 五、通知配置

两条通道可同时启用，互不影响：

1. **Bark**（项目自带）：配 `LYNKCO_BARK_KEY`，推送 Markdown 版结果，含签到奖励、连续天数、分享文章标题、积分变化。
2. **青龙面板通知**：自动查找 `sendNotify.py` / `notify.py` / `notify.js`，走面板「系统设置 → 通知设置」里配的渠道（PushPlus、Server 酱、钉钉、企业微信、Telegram、Bark 等）。找不到就跳过，结果仍在任务日志里。

## 六、日志与结果判读

任务启动会先打印一份「配置自检」，看不到密钥明文，只显示位数与脱敏片段，方便在面板里直接排障：

```

[08:08:00] 脚本目录: /ql/scripts/LynkCoHelper/LynkCoHelper
[08:08:00] env 文件 : /ql/data/lynkco_env.json
[08:08:00] 当前时间 : 2026-09-30 08:08:00 (UTC+8)
[08:08:00] 账号数量 : 2
[08:08:00] LYNKCO_APP_SECRETS    : 已配置（146 位，字段 5 个：glDevId,loginAppCode,nativeAppCode,nativeAppKey,nativeAppSecret）
[08:08:00] LYNKCO_REFRESH_TOKEN  : 2 个
[08:08:00] LYNKCO_BARK_KEY       : tes***ey(11位)
...
[08:08:06] 全部执行完毕：共 2 个账号，成功 2 个，失败 0 个。
```

退出码：`0` 全部成功 / `1` 存在失败账号。青龙据此标记「正常 / 异常」。

## 七、常见问题排查

| 现象 | 原因与处理 |
| --- | --- |
| `缺少必需的签名密钥 XXX` | `LYNKCO_APP_SECRETS` 未配置或 JSON 字段名拼错（注意是驼峰 `nativeAppKey`）；脚本自检段会显示实际解析到的字段列表 |
| `接口未返回有效 JSON … HTTP 401 Invalid Key` | 密钥本身过期/错误，或 App 版本升级换了 key，需重新提取 AppSecret |
| `refreshToken 续期失败，两套认证方案均未成功` | refreshToken 已过期（约 30 天），需重新抓包或重跑一次登录流程 |
| `未找到有效的 token` | 既没配 `LYNKCO_REFRESH_TOKEN` 也没配 `LYNKCO_TOKEN`，且没有可用的 env.json |
| 日志里时间是 UTC | 青龙容器未设时区，添加环境变量 `TZ=Asia/Shanghai` |
| 任务秒退、无日志 | 青龙的 python3 异常，先手动跑 `python3 /ql/scripts/.../lynkco_qinglong.py` 看报错；依赖缺失时脚本会自动装 requests，装不上会在日志里给出提示 |
| 分享任务一直失败但签到正常 | 分享接口每日有加分上限，接口返回 success 也不代表加分；可用 `LYNKCO_DO_SHARE=0` 先关掉 |
| 拉库后多了很多任务 | 订阅的「自动添加任务」给每个 py 都建了任务，删除多余项只留 `lynkco_qinglong.py` |
| 多账号串号 | 已自动规避（多账号时关闭 env.json 缓存与回写）；若仍异常，确认 `LYNKCO_DEVICE_ID` 与 refreshToken 一一对应 |

## 八、升级与维护

- 拉库方式：订阅定时拉取即可自动更新；源码有改动时重新触发一次同步。
- 单文件方式：仓库更新后重新执行打包器，或重新粘贴新版单文件。
- `env.json`（`/ql/data/lynkco_env.json`）只作本地缓存留档，删除后脚本会自动走 refreshToken 续期重新生成。
