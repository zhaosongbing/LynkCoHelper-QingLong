# 拉库时自动创建青龙定时任务

> 目标：`ql repo` / 订阅拉库之后，青龙面板里**自动出现**「领克·每日签到分享」这类任务，
> 任务名、定时规则、启用状态都由仓库里的清单说了算，重复拉库不会建重，仓库删掉的任务会被清理。

## 1. 首选方案：脚本头部的 cron / name 声明（面板原生，零配置）

青龙 2.x 与呆呆面板（Dumb-Panel）这类分支在**拉库之后会扫描每个脚本的头部**，按注释里的
`cron` / `name` 声明自动建定时任务。本项目已经在入口脚本里写好声明，拉库即可见效：

```python
# LynkCoHelper/lynkco_qinglong.py 第 3～4 行
# cron: 8 8 * * *
# name: 领克·每日签到分享
```

只要订阅开了「自动添加任务」，拉库后面板就会出现一条任务：

| 项 | 值 |
| --- | --- |
| 任务名 | 领克·每日签到分享 |
| 命令 | `task LynkCoHelper-QingLong/LynkCoHelper/lynkco_qinglong.py` |
| 定时规则 | `8 8 * * *`（每天 08:08） |

**改定时规则 = 改这两行 + 重新拉库**，不需要动面板里的任务（重复拉库按命令匹配，不会建重）。

### 面板认声明的规则

下面是从 daidai-panel 源码（`server/service/subscription.go`、`server/pkg/cron/cron.go`）抄下来的确切口径，
青龙同系分支基本一致：

| 项 | 规则 |
| --- | --- |
| 扫描范围 | 每个脚本**前 120 行**；认不出就不建任务（除非订阅里填了「默认 Cron 规则」，那会按默认规则给所有脚本建） |
| 定时规则 | 正则 `^([\s#*@/]*)@?cron\b\s*[:：]?\s*(\S.*)$`，即注释标记（`#` `//` `*` `@`）后的 `cron` / `@cron`，冒号可有可无 |
| 规则取值 | 值本身必须是合法的 5 段（`分 时 日 月 周`）或 6 段（`秒 分 时 日 月 周`）cron；行尾带了说明文字时只取前 5 / 6 段；成对引号包住整个值时能剥掉引号 |
| 任务名 | 先认 `new Env('名称')`，再认注释里的 `name: 名称`，都没有就回退成文件名 |
| 辅助脚本 | 没有声明、且文件名是 `sendNotify` / `notify` / `utils` 这类辅助脚本的，不会建任务 |

写法示例（都能认）：

```python
# cron: 8 8 * * *          # Python
#cron 8 9,10,11 * * *      # 无空格、无冒号
# cron: "0 8 * * *"        # 带引号
```

```js
// cron: 0 0 * * *         // JS 行注释
/* cron: 0 0 * * * */      // 块注释
 * cron: 12 8 * * *        // JSDoc 每行带 *
```

### 自查仓库里哪些脚本会被建任务

```bash
python3 LynkCoHelper/tools/check_cron_decl.py
```

按同一套正则复算一遍并列出结果，当前应当只有一条：

```
会被自动建任务的脚本 1 个：
  · LynkCoHelper/lynkco_qinglong.py
      定时规则 8 8 * * *    任务名 领克·每日签到分享
```

> 整仓拉库时 `qinglong/lynkco_qinglong_single.py` 也会被扫到，但它**默认不带声明**
> （打包器会剥掉 `cron` / `name` 行），不会与多模块版重复建两条任务。
> 只用单文件版、又想自动建任务的场景，生成时加参数：
> `python3 LynkCoHelper/tools/build_qinglong_single.py --cron "8 8 * * *" --name "领克·每日签到分享"`。

### 什么情况下改用第 2 节起的 OpenAPI 方案

面板原生方案够用时就别折腾；以下场景才需要 `lynkco_ql_tasks.py`：

- 要给任务打标签、填备注；
- 想用「固定间隔」（`45s` / `30m` / `2h`）而不是 cron；
- 想按状态文件精确清理仓库里已下线的任务（`sync --prune`）；
- 面板版本不认 cron 声明，或者「自动添加任务」开关不可用。

## 2. 背景：青龙到底会不会自动建任务

| 机制 | 行为 | 问题 |
| --- | --- | --- |
| `ql repo` / 订阅拉库 | 只把脚本文件同步到 `/ql/data/scripts/<仓库名>/` | **不会**建任务 |
| 订阅里勾选「自动添加任务」（`AutoAddCron`） | 按白名单把每个脚本文件建成一条任务 | 定时规则统一取 `config.sh` 的 `DefaultCronRule`（默认 `0 3 * * *`），任务名=文件名，规则不受控；仓库脚本多时会建出一堆无用任务 |
| 「自动删除任务」（`AutoDelCron`） | 仓库里删掉的脚本，对应任务一并删除 | 与上面配套，但同样基于文件名匹配 |

所以「自动建任务」这件事青龙只做了一半（建得出来、建不对）。本项目的做法是：

1. 仓库里放一份**声明式清单** `LynkCoHelper/qinglong_tasks.json`（任务名 / 命令 / cron / 标签 / 是否启用）；
2. 拉库后由青龙执行一次 `lynkco_ql_tasks.py sync`，通过青龙 **OpenAPI** 把清单**幂等**同步进面板；
3. 青龙自己建出来的任务（按 command 匹配）也会被认出来并校正成清单里的规则，**不会重复创建**。

## 3. 三种触发时机（任选，建议同时配前两种）

### 方式一：订阅的「执行后」命令（最省事）

订阅管理 → 编辑订阅 → 「执行后」填：

```bash
task LynkCoHelper-QingLong/LynkCoHelper/lynkco_ql_tasks.py sync
```

此后每次拉库结束，青龙立刻执行这条命令，任务就被建好/校正好。
（如果你的青龙版本 `task` 不传参，改用：
`python3 /ql/data/scripts/LynkCoHelper-QingLong/LynkCoHelper/lynkco_ql_tasks.py sync`）

### 方式二：清单自带一条「任务注册同步」任务（双保险）

`qinglong_tasks.json` 里默认就带了这条（每周一 03:17 执行一次 `sync`），
即使没配「执行后」，每周也会自动校正一次任务名与规则。

### 方式三：手动跑一次

```bash
ql repo https://github.com/zhaosongbing/LynkCoHelper-QingLong.git "LynkCoHelper" "docs|previews|tools" "requirements.txt" "main"
python3 /ql/data/scripts/LynkCoHelper-QingLong/LynkCoHelper/lynkco_ql_tasks.py sync
```

## 4. 订阅 / 拉库参数

| 字段 | 填写值 | 说明 |
| --- | --- | --- |
| 名称 | `LynkCoHelper` | 任意 |
| 类型 | 公开仓库 / 私有仓库 | 私有仓库需填 SSH 私钥或用户名+Token |
| 链接 | `https://github.com/zhaosongbing/LynkCoHelper-QingLong.git` | 注意是 `-QingLong` 这个仓库，原仓库没有青龙适配代码 |
| 分支 | `main` | |
| 定时类型 / 规则 | crontab `0 3 * * *` | 这是「多久检查一次仓库更新」，不是签到时间 |
| 白名单 | `LynkCoHelper/lynkco_\|qinglong_tasks\.json` | 只收入口脚本与清单，避免把 tools/ 下的一堆脚本也拉进来 |
| 黑名单 | `docs\|previews\|tools\|tests` | |
| 依赖文件 | `requirements.txt` | 自动安装 requests |
| 文件后缀 | `py` | 默认 `js py` 即可 |
| 自动添加任务 | **开启** | 第 1 节的 cron 声明靠这个开关生效；开着也不会与清单建重（按命令匹配后校正） |
| 自动删除任务 | 建议开启 | 仓库里删掉的脚本，其任务一并删除；需要精确控制时再关掉、交给 `sync --prune` |
| 执行后 | `task LynkCoHelper-QingLong/LynkCoHelper/lynkco_ql_tasks.py sync` | 用第 1 节方案时可不填；用 OpenAPI 方案时必填 |

> 白名单里若包含 `lynkco_ql_tasks.py`，它自己会被拉下来，「执行后」命令才能跑；
> 若把它排除掉，就只能用方式二 / 方式三。
>
> 白名单别只填 `LynkCoHelper`：仓库目录名 `LynkCoHelper-QingLong` 本身也含这个子串，
> 子串匹配会让全仓文件都进候选（表现为「扫描到 19 个候选文件」）。建议写成
> `LynkCoHelper/lynkco_` 这类带路径的写法。

## 5. 鉴权配置（三选一）

`lynkco_ql_tasks.py` 调的是青龙 OpenAPI（`/open/*`），需要凭据：

| 优先级 | 方式 | 说明 |
| --- | --- | --- |
| 1 | 环境变量 `QL_TOKEN` | 面板 token，最简单。青龙「系统设置 → 安全设置」可查看/重置 |
| 2 | `/ql/config/auth.json` 的 `token` 字段 | 老版本面板容器内自带，无需配置 |
| 3 | `QL_CLIENT_ID` + `QL_CLIENT_SECRET` | 面板「系统设置 → 安全设置 → 应用」新建应用，**必须勾选 `crons` 权限**；脚本会 `GET /open/auth/token` 换 token |

凭据可以放在青龙「环境变量」里（`QL_TOKEN`），也可以在容器里 `export`。
`QL_BASE_URL` 默认是 `http://127.0.0.1:5700`，端口改过就显式配置。

自检命令（会把连通性、凭据、时区、清单一次性查完）：

```bash
task LynkCoHelper-QingLong/LynkCoHelper/lynkco_ql_tasks.py status
```

## 6. 任务清单 `qinglong_tasks.json`

```json
{
  "version": 1,
  "defaults": { "labels": ["LynkCo"], "timezone": "Asia/Shanghai", "enabled": true },
  "tasks": [
    {
      "name": "领克·每日签到分享",
      "command": "task {repo}/LynkCoHelper/lynkco_qinglong.py",
      "script": "{repo}/LynkCoHelper/lynkco_qinglong.py",
      "schedule": "8 8 * * *",
      "description": "每日签到 + 分享 + 积分查询",
      "enabled": true
    },
    {
      "name": "领克·面板连接自检（示例·默认停用）",
      "command": "task {repo}/LynkCoHelper/lynkco_ql_tasks.py status",
      "interval": "6h",
      "enabled": false
    }
  ]
}
```

### 字段说明

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `name` | ✅ | 任务名，**唯一**；清单内重名直接报错 |
| `command` | ✅ | 青龙任务命令，如 `task <脚本相对路径>`；**也是去重主键**，清单内重复会报错 |
| `schedule` | 二选一 | cron 表达式，5 段（分 时 日 月 周）或 6 段（秒 分 时 日 月 周，青龙支持秒级） |
| `interval` | 二选一 | 固定间隔，支持 `45s` / `30m` / `2h` / `1d` 或整数秒；会折算成 cron（见下） |
| `script` | 否 | 脚本相对路径，用于校验文件是否真的被拉下来（不填则从 command 里提取） |
| `labels` | 否 | 标签数组，默认取 `defaults.labels` 或 `LynkCo` |
| `enabled` | 否 | 默认 `true`；`false` 表示注册但**不立即生效**（面板里为停用状态） |
| `description` | 否 | 备注 |
| `timezone` | 否 | 声明时区，仅用于与面板时区比对告警（cron 始终按面板时区解释） |
| `{repo}` 占位符 | — | 自动替换为脚本所在的仓库目录名（如 `LynkCoHelper-QingLong`），换仓库名/Fork 不用改清单；本地运行可用 `LYNKCO_QL_REPO` 指定 |

### 间隔 → cron 折算规则

青龙的 cron 任务只认表达式，因此间隔会按量级折算：

| 间隔 | 折算结果 |
| --- | --- |
| `45s` | `*/45 * * * * *` |
| `30m` / `1800` | `*/30 * * * *` |
| `2h` | `0 */2 * * *` |
| `1d` | `0 0 */1 * *` |

不能整除时（如 `45m`）会给出告警——触发不均匀，建议直接写 cron。超过 31 天直接报错。

## 7. 幂等、去重与清理

- **匹配顺序**：先按 `command` 精确匹配，再按 `name` 匹配。命中即视为同一条任务。
- **已存在且一致** → 不动（日志 `[一致]`）。
- **已存在但规则/名称/标签/启用状态不同** → `PUT /open/crons` 校正（日志 `[更新]`），
  加 `--no-update` 可只补建缺失任务、不动已有任务。
- **不存在** → `POST /open/crons` 新建（日志 `[新建]`）。
- **清理**：`sync --prune` 会删除「状态文件里记录过、但本次清单已不含」的任务。
- **状态文件**：默认 `/ql/data/lynkco_ql_tasks_state.json`，记录 `任务名 → 青龙任务 id`，
  面板重启、重新拉库后都能恢复对应关系，不会重复创建。
- **试运行**：`sync --dry-run` 只打印将要做的变更，不发任何写请求、不写状态文件。

## 8. 命令行一览

```bash
python3 lynkco_ql_tasks.py status                       # 连通性/凭据/时区/清单自检
python3 lynkco_ql_tasks.py sync [--dry-run] [--prune] [--no-update] [--run-now] [--file 清单]
python3 lynkco_ql_tasks.py validate [--file 清单]        # 只校验清单，不联网
python3 lynkco_ql_tasks.py list [--json] [--search 关键字]
python3 lynkco_ql_tasks.py add --name "任务名" --command "task x.py" --schedule "8 8 * * *" [--interval 6h] [--disabled] [--run-now]
python3 lynkco_ql_tasks.py remove "任务名或id" [--dry-run]
python3 lynkco_ql_tasks.py run "任务名或id"
```

退出码：`0` 全部成功，`1` 存在失败项（青龙可据此标红任务并触发「任务失败时推送」）。

| `LYNKCO_QL_NOTIFY` | `0` | 同步失败时是否走面板通知渠道推送 |

## 10. 排障

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `[鉴权失败] 未找到青龙面板凭据` | 三种凭据都没配 | 配 `QL_TOKEN` 或 `QL_CLIENT_ID/SECRET`（应用需 `crons` 权限） |
| `青龙面板拒绝访问（HTTP 401/403）` | token 过期/无效，或应用没勾 `crons` | 重置 token；应用权限里勾选 `crons` |
| `HTTP 400 Invalid path format` | 请求路径含大写字母 | 脚本已全小写处理，若自行改代码注意 `/open/*` 必须小写 |
| `青龙面板返回 code=400`（创建时） | 新版 OpenAPI 的 `POST /open/crons` 只接受**单个对象** | 脚本已按单对象逐条创建，未走批量 |
| `[警告] 脚本 … 不存在` | 没拉到库 / 白名单没包含该脚本 / 路径写错 | 先看拉库日志，再 `validate`；确认 `LYNKCO_QL_SCRIPTS_DIR` |
| `[警告] 清单声明时区 … 面板时区为 …` | 容器 TZ 与清单不一致，cron 按面板时区解释 | 青龙设环境变量 `TZ=Asia/Shanghai` 并重启面板 |
| 任务建出来了但没跑 | 任务被建为停用，或面板调度未刷新 | `list` 看 `isDisabled`；`run "任务名"` 手动触发验证 |
| 老版本青龙调不通 `/open/*` | 2.13 以下没有 OpenAPI | 改用清单里的每周 sync 任务 + 面板手动建，或升级青龙 |
